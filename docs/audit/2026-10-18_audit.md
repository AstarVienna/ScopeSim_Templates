## 1. Packaging and release hygiene

- **Upper pin on ScopeSim (`<0.12.0`).** This is the biggest obstacle to supporting ScopeSim. Relax it to
  `>=0.11.2,<0.13` (or drop the cap) and add a CI job that tests against ScopeSim `main`.
- **Over-tight upper caps on everything.** `scipy (>=1.17.0,<1.18.0)`, `numpy <2.3` on Python ≤ 3.12, `astropy <8`, and so on.
  For a *library*, upper caps cause resolver conflicts downstream. The lower bounds are fine (keep them, and keep the lock
  file for CI).
- **Unused runtime dependencies.** `beautifulsoup4`, `lxml` and `docutils` are imported nowhere. `matplotlib` is only
  imported in tests and the docs scripts, so move it to the test/docs groups. `pyyaml` is only used by viking_fields
  (that's fine, but note it).
- **Wheel contents** (built with `uv build`, 83 files):
  - `scopesim_templates/misc/NGC6888_Starless.fits` (11.3 MB, untracked but *not* gitignored, so poetry includes it).
    **This would have shipped if a release had been cut from this checkout.**
  - `micado/viking_fields/field_*.eps` (3 × ~600 kB): figures, not data.
  - `stellar/mamajek.dat` (55 kB): unused. Only `mamajek_alt.dat` is read.
  - The entire `scopesim_templates/tests/` tree.
  - Fix: add `exclude = [...]` to `[tool.poetry]`, or move the tests to the top-level `tests/` and delete the dead
    `MANIFEST.in`.
- **Version bookkeeping.** `version.py` has two sources of truth: `metadata.version()`, plus a hand-written YAML
  changelog frozen at 0.5.2 with a 2024 date. Expose `scopesim_templates.__version__`. Keep the changelog in
  `CHANGELOG.md` or the GitHub releases, not in Python source.
- **`docs/conf.py`** hard-codes `version = '0.4'`. Read it from `importlib.metadata` instead.
- **The `.gitignore` pattern `data`** ignores any path component named `data`. `micado/data/` only survives because
  it was force-added. That trap will bite whoever adds the next data directory.
- **Committed `docs/notebooks/.ipynb_checkpoints/`**, even though `.gitignore` lists them.
- **Maintainer email typo:** `kieran.leschinski@unive.ac.at`.

## 2. Correctness bugs

All of these are **[confirmed]** unless marked *(by reading)*.

### Crashes
| Call | Result | Cause |
|------|--------|-------|
| `scopesim_templates.micado.pinhole_mask()` | `TypeError: missing x, y, waves` | Zero-arg wrapper around a function that needs 3 args (`micado/__init__.py:27-29`) |
| `from scopesim_templates.micado import *` | `TypeError: Item in __all__ must be str` | `__all__ = [darkness, ...]` (`micado/__init__.py:37`, `micado/darkness.py:4`) |
| `vf.load_stars_source(ra=10, dec=-30)` | `UnboundLocalError: ra0` | `ra0`/`dec0` are only assigned in the `None` branch (`viking_fields.py:98-102`) |
| `vf.load_galaxies_source(ns=...)` | `UnboundLocalError: n_gals` | `n_gals` is only assigned inside `if ns is None` (`viking_fields.py:169-188`) |
| `star_field(..., seed=1)` | `TypeError: stars() got unexpected kwarg 'seed'` | `**kwargs` is forwarded wholesale to `stars()` (`stellar.py:93`) |
| `galaxy(sed=<synphot.SourceSpectrum>)` | `AttributeError: no attribute 'redshift'` | `isinstance(sed, Spextrum.__bases__)` accepts plain `SourceSpectrum`, then calls a Spextrum-only method. Any other type leaves `spec` unbound → `UnboundLocalError` (`galaxies.py:100-105`) |
| `function_call_str` with too many positional args | `StopIteration` (comment at `general_utils.py:48` admits it) | Iterates over `signature.parameters` and runs off the end. Also swallows `**kwargs` as `kwargs=99`. This runs inside the decorator, so a bug in *metadata generation* crashes *source creation*. |

### Silent wrong results
- **`load_galaxies_source`:** `src.fields[0].data *= scale_factors[0]` (`viking_fields.py:208`) should be `[i]`, so every
  galaxy has the first galaxy's flux. The `random_seed` argument of `viking_field()` is also accepted but never passed on
  (`viking_fields.py:71-73`).
- **`stars(..., library="kurucz")`:** one spectrum is built *per star* (already scaled to that star's amplitude), but
  `ref` indexes into `unique_types`. Two A0V stars at 10 and 15 mag both point at spectrum 0, so both come out at 10 mag
  (`stellar.py:243-252`, by reading).
- **`make_img_wcs_header(image_size=arr.shape)`:** the docstring says `(x, y)`, but callers pass NumPy's `(ny, nx)`. For a
  10×30 array the result is CRPIX = (5.5, 15.5); it should be (15.5, 5.5). This affects `source_from_array`,
  `source_from_file`, `galaxy` and `uniform_source`.
- **MICADO `line_list`:** `im = np.ones((NAXIS1, NAXIS2))` uses FITS axis order for a NumPy array. The 15″×1″ slit
  image ends up with data shape `(20, 1)`, but the WCS has CRPIX1 = 10.5, so it is transposed
  (`spectral_calibrations.py:88-101`). `metis/laser.py:60-73` copy-pastes the same code ("Taken from…") and inherits
  the bug; it only works because the default image is square.
- **MICADO `flatlamp`:** the centre is computed in arcsec (`(width-1)/2`), not pixels. On the default 20×20 image the
  peak is at (10, 10) with CRPIX 11.0, so it is off by ½ px (`flatlamp.py:48-49`).
- **`star_field` metadata** always records `filter_name="V"`, whatever was passed (`stellar.py:66`).
- **`spiral_two_component`:** the `fluxes` and `offset` parameters are accepted and silently ignored (TODO, `galaxies.py:299-300`).
  The trailing comma in `header["CRPIX1"] = (w + 1) / 2,` only works by accident, because astropy treats the 1-tuple as `(value,)`.
- **`galaxy3d(sed=<Spextrum>)`** silently ignores `z` and `amplitude` (`galaxies.py:206-207`).
- **`elliptical`:** `spectrum.z = params["redshift"]` sets an attribute that synphot ignores, so redshift has no effect
  (`galaxies.py:427`, by reading). Its docstring says "This docstring is from simcado, needs to be updated".

### Input mutation / side effects
- `stars()`: `spec_types *= len(x)` mutates the caller's list (`stellar.py:256`).
- `source_from_imagehdu_with_flux`: `header = image_hdu.header`, then `.update(...)` overwrites the caller's
  CRVAL, CDELT and BUNIT (`misc.py:271-292`).
- `source_from_imagehdu`: writes `SPEC_REF` into the caller's header (`misc.py:222-223`).
- `source_from_file`: `fits.open()` is never closed (this locks the file on Windows), and `data[data < cut] = 0`
  mutates the HDU (`misc.py:376-383`).
- **The global RNG** (see TL;DR #2). Use `np.random.default_rng(seed)` and pass the generator down.
  `globular_cluster` is half-migrated: it builds a `Generator` *and* calls `np.random.seed` because `imf.py`
  still uses the legacy global API.

## 3. API design and backwards-compatibility debt

- **Same name, different signature.** `scopesim_templates.cluster` is the stellar cluster. `scopesim_templates.micado.cluster`
  is a zero-arg MICADO preset, and `micado.empty_sky` is a "backwards compatibility" alias marked "TODO: Remove when
  not used in MicadoWISE". `metis.pinhole_mask` and `micado.pinhole_mask` have unrelated signatures.
- **Inconsistent parameter names** for the same concept: `filter_name` / `filter_curve`, `amplitude` / `amplitudes` / `mmin`+`mmax`,
  `ellip` / `ellipticity`, `theta` / `angle`, `extend` / `extent`, `r_eff` sometimes in px and sometimes in arcsec.
  Only some functions take `ra`/`dec`, and those that do don't use them ("not used at the moment").
- **Inconsistent metadata.** Some functions use `@add_function_call_str`, some build `params["function_call"]` by hand,
  and some (`star`, `star_field`, `elliptical`, `source_from_cube`, `micado.flatlamp`) have neither, so `src.meta`
  is unpredictable.
- **Inconsistent default magnitude systems:** Vega for `stars`, AB for `point_source` and `elliptical`.
- **Stubs and placeholders in the public API.** `source_from_moments()` and `make_cube_wcs_header()` raise
  `NotImplementedError`. `extragalactic/{agns,quasars,clusters}.py` are empty and star-imported. `poorman_cube_source`
  builds two unused lists (`hdus`, `specs`) and adds Sources in a loop, which is O(n²).
- **A deprecation that never finished.** `source_from_image` has emitted `PendingDeprecationWarning` since **0.3.0** and
  is still re-exported at the top level. The `deprecated_renamed_argument` shims date from "0.1".
- **Coupling to ScopeSim internals.** `rc.py` reaches into `scopesim.source.source.Source` and
  `scopesim.optics.image_plane_utils.create_wcs_from_points`. Any internal refactor in ScopeSim breaks templates.
  This is why the version pin exists at all. Agree a small public surface with ScopeSim, or vendor
  `create_wcs_from_points`. `rc.__config__` is a dunder name used as public config.
- **Wildcard imports** (`from .galaxies import *`, etc.) plus a mixture of `__all__` styles.
- **`assert` used for input validation** (`hdu_to_synphot`, `line_list`, `galaxy3d`, `poorman_cube_source`). These
  checks vanish under `python -O`.
- **Logging.** `add_function_call_str` logs via the *root* logger (`logging.debug`). `imf.py` uses `getLogger("imf")`.
  There is no package logger.
- **Warnings that apologise for themselves.** `calibration.lamp` and `flat_field` raise `RuntimeWarning` on every call,
  next to the comment "I don't understand this warning but it probably has a reason…".

## 4. Testing

**Clean-env run** (Python 3.11, numpy 2.2.6, ScopeSim 0.11.4, speXtra 0.43.5):
`98 passed, 5 failed, 8 errors, 1 skipped in 358 s` · **coverage 73%**.

- **Failures are environmental but systemic.** `~/.spextra_cache/svo_filters/SLOAN/SDSS.g` holds an HTML page
  (a German-language captive portal or error page) instead of a VOTable. Every test that touches filter `"g"` fails,
  and the module-scoped fixture in `test_validate_content.py` turns that into 8 errors. Tests must not depend on an
  unisolated user-level cache or on live SVO and DLC servers.
- **Slow.** The five viking-field tests take 187 s, all spent building 1131 Sersic images in a Python loop.
  `test_runs_through_scopesim_basic_instrument` alone takes 87 s.
- **Untested or barely tested:** `samplers.py` (12%), `metis/laser.py` (29%), `imf.py` (48%), `exgal_models.py`
  (57%, so `VelField` and `DispersionField` are never evaluated), `galaxy3d`, `source_from_file`,
  `source_from_imagehdu_with_flux`, `source_from_cube`, and the `library != "pyckles"` path of `stars`. Every
  bug in §2 slipped through.
- **Weak assertions.** Most tests are `assert isinstance(src, Source)`. Few tests check flux conservation, WCS
  correctness, determinism under `seed`, or that inputs aren't mutated.
- **Test-code smells.** `METIS_FILTER_PATH = r"F:/Work/irdb/..."` ("only works on Kieran's local machine"),
  `if PLOTS:` blocks with `plt.show()` and a `matplotlib` import in about 6 files, `test_rc.py` asserts nothing
  (`isinstance(...)` without `assert`), `_basic_imagehdu` loops over `x, y` but always writes `im[0] = 1`, and
  `"TODO: Figure out why source is not in the center!"` (with fudge = 100 px).
- **The tests live inside the package** (`scopesim_templates/tests`), so they ship to users.

## 5. Code quality and maintainability

- **`imf.py` (983 lines) is vendored** from PyPopStar/SPISEA (`vers:134c5ff`, 2020). About half of it is unused (log-normal
  helpers, multiplicity, `Miller_Scalo`, `Kennicutt`, ...). Its GPL provenance is noted but not reflected in a
  `NOTICE`. It drives the global RNG.
- **`_gillessen.py`** is "vendored from the standalone `gillessen` script collection". Fine, but the Kepler and
  Thiele–Innes helpers are now imported by `globular_cluster.py` through `_`-private names. Promote them to a
  shared `utils/orbits.py`.
- **Duplicated code:** the WCS-from-points block (micado `line_list`, metis `laser_spectrum`, `elliptical`), the TODO
  "This is WET with create_wcs_from_points" in `general_utils.py:81`, and three different spectrum-scaling idioms.
- **`samplers.randomvariate`** has an unbounded `while` loop that only increments `ntrial` on acceptance (a bug), and
  a commented-out Python 2 `print`.
- **Viking fields** call `Spextrum("brown/NGC0584")` at runtime (network), and their docstrings refer to people
  ("Ric's input", "speak to Carmelo Archidiacono").
- **Commented-out code** is scattered throughout (`misc.py:378-381, 446, 481`, `galaxies.py:262, 292, 302-305`, `cluster_utils.py:169-174`).
- **No type hints** except in the newest modules. No linter or formatter config (ruff, pre-commit) in the repo.

## 6. Documentation

- The README "templates included" list is out of date (see TL;DR #10) and has typos ("This packages contain",
  "easy the creation", "spacial", "othe").
- `TODO.md` is a 2020-era wish list mixed with things that now exist (`galactic_center`, `pinhole_mask`,
  `from_cube`).
- Many docstrings are incomplete or wrong: `source_from_file` has an empty Parameters section, `metis.pinhole_mask`
  returns "TYPE / DESCRIPTION", `laser_spectrum` documents its arguments as "TYPE", the `star` docstring is copied from
  `stars` (wrong parameter names), and `cluster` says "Max = 1E5 Msun" and calls multiplicity "Not sure what it does".
- There is no "units and conventions" page covering arcsec vs deg, Vega vs AB defaults, pixel vs arcsec `r_eff`, and
  the `x`/`y` sign convention. Many of the bugs in §2 come from exactly this ambiguity.
- CI runs doctests (`docstring_tests.yml`), but many examples hit the network or `scopesim.download_packages`.

## 7. CI / tooling

- `tests.yml` delegates entirely to `AstarVienna/DevOps/...@main`. That's reasonable for an org, but it is pinned to
  a moving branch and can't be reproduced locally.
- No lint step, no wheel-content check, no "test against ScopeSim `main`" job, and no minimum-versions job. The last
  one would have caught the `np.trapezoid` vs `numpy 1.26` problem.
- The dev environment on this machine is badly stale: global Python has speXtra 0.31, pyckles 0.2, and templates
  metadata 0.4.4 from an old `egg-info`. A stray `ScopeSim_Templates.egg-info/` sits in the repo root. Use a
  project-local `uv` venv.

## Suggested overnight plan (in order, each step a separate commit/PR-sized chunk)

1. **Environment and safety net.** Set up a `uv` venv (`uv venv && uv pip install -e . pytest pytest-cov`) and isolate
   caches in tests (`SPEXTRA_CACHE`/tmp dir via a fixture). Add a `conftest.py` with an autouse fixture that
   asserts the global NumPy RNG state is unchanged after each test. Move the tests to the top-level `tests/`.
2. **Packaging.** *(The ScopeSim pin and unused dependencies are already done upstream.)* Fix `np.trapz` → `np.trapezoid` in
   `samplers.py`, which is broken on numpy 2.5. Move `matplotlib` to the test/docs groups. Add wheel `exclude`s for tests,
   `.eps` and `mamajek.dat`, and delete `MANIFEST.in` and the `.ipynb_checkpoints`. Expose `__version__`, remove the
   stale `version.py` changelog, and read the docs version from metadata.
3. **Characterisation tests first**, then fix every bug in §2 with a regression test per bug. Highest value:
   viking `scale_factors[i]`, `stars()` non-pyckles ref, the WCS axis-order bugs, and the micado crashes.
4. **RNG.** Thread `np.random.Generator` through `imf.py`, `cluster_utils`, `stellar`, `viking_fields` and `samplers`. Keep
   accepting `seed=int` for backwards compatibility. Stop reseeding the global state.
5. **No input mutation.** Copy headers and lists at function entry.
6. **Consistency.** Apply `@add_function_call_str` everywhere, make `function_call_str` robust (it must never raise
   inside the decorator), and add a package logger.
7. **Deprecations.** Emit proper `DeprecationWarning`s for the 0.1/0.3-era aliases, with a removal version. Don't

## Maintainer decisions (2026-10-19)

1. **RNG:** no seed is set by default, and default output may change. Every stochastic function accepts `seed`
   (an `int` or a `np.random.Generator`) for reproducibility. The global NumPy RNG is never touched.
2. **Wrong output is fixed**, even when the numbers change.
3. **MicadoWISE aliases** get a `DeprecationWarning` but are **not removed**.
4. **`kl/hudf_template` is merged** (`8dc14db`). Its bugs (absolute CRVAL, PA in deg vs rad) are fixed during the refactor.
5. **New templates** come from the MAVIS 2026 feasibility studies (`D:\tmp\mavis_workshop_2026`): the Galactic Centre
   with a background population (e.g. 3000 Msun), a time-evolved S301 population, and a time-evolved ω Cen population.
   The HUDF template is reconciled with the workshop's `hudf.py`.
6. **Vendoring:** catalogue files under 1 MB may be vendored, with attribution.
7. **No PyPI release or tag is published without explicit confirmation.** The release is prepared only.
